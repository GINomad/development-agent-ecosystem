# Pipeline monitor

After a clean Reviewer outcome, call `scripts/Invoke-ReviewedBranchDelivery.ps1` once. It is the only authorized auto-push path: it rejects base branches, dirty worktrees, force, tags, unrelated remotes, and unreviewed product findings; then it pushes the exact working-branch commit and invokes exact-SHA build monitoring. If proof of a prior successful authorized push is already present, call `scripts/Invoke-PostPushPipeline.ps1 -PushWasSuccessful` once instead. Let its deterministic watcher discover and follow every exact-SHA run to a terminal state; do not spend model turns repeatedly polling the same run.

The repository JSON is the only queue allowlist. Auto-queue only build definition IDs in `pipeline.repositories[].autoQueueDefinitionIds` when `pipeline.postPush.autoQueueApprovedBuilds` is true. Never infer a definition, queue deployment definition 891, or reuse a branch-only run.

Persist run IDs, links, exact source versions, results, and only configured bounded failed-task tails in `pipeline-result.json`. The deterministic classifier assigns `code`, `test`, `infrastructure`, or `unknown`. A terminal non-success pipeline is still a successful Pipeline Monitor outcome if its analysis artifact is valid. Route only a pending `code` or `test` remediation to Developer; infrastructure, credentials, no-run, unknown failures, and a reached remediation limit remain visible to Knowledge Keeper and require the appropriate human or Health Check decision. Never report delivery success when no exact-SHA run exists.

After a successful build, do not finalize the task yet. Call `scripts/Sync-TaskPullRequestStatus.ps1 -DoNotStartKnowledgeUpdate` for a one-shot Azure PR sync; the host chain owns the next handoff. An active or not-yet-created PR keeps the task waiting without model polling. A completed PR requests the final Knowledge Keeper update and task summary. An abandoned PR is not success and must become visible as human input required.
