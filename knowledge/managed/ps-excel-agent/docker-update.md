## PR review findings

### 1. High: runtime `env.js` in Docker may be shadowed by static file

In `Dockerfile`, React `dist` is copied into `wwwroot`:

```dockerfile
COPY --from=react-build /app/dist ./wwwroot
```

After `npm run build`, `planningspace.integration.excel.ui\dist\env.js` exists.

In `Program.cs`, `UseStaticFiles()` is registered before `app.Map("env.js", ...)`, so static `wwwroot/env.js` can be served before the dynamic runtime config route.

Suggested fix:

```dockerfile
COPY --from=react-build /app/dist ./wwwroot
RUN rm -f ./wwwroot/env.js
```

Alternative fix: map dynamic `env.js` before static files.

### 2. Medium: Docker port mismatch risk

`Dockerfile` has:

```dockerfile
EXPOSE 80
```

Modern ASP.NET container images commonly listen on `8080` unless configured otherwise. This can cause the container to run but not respond on the expected port.

Suggested fix option A:

```dockerfile
ENV ASPNETCORE_HTTP_PORTS=80
EXPOSE 80
```

Suggested fix option B:

```dockerfile
EXPOSE 8080
```

Then run locally with `-p 8080:8080`.

### 3. Low/Medium: feed token passed through Docker build arg/env

`Dockerfile` uses:

```dockerfile
ARG FEED_ACCESSTOKEN
ENV VSS_NUGET_EXTERNAL_FEED_ENDPOINTS=...
```

The final image probably does not contain this env var because it is a different stage, but build args/env can still leak via build metadata/cache depending on builder settings.

Safer long-term option: Docker BuildKit secrets.

### CORS investigation

Browser error path:

```text
https://wa-excelagent-dev-001.azurewebsites.net
  -> https://ps-dev-cluster01.qdev.net/null/api/tenanthome/getversion
```

Two independent problems were confirmed:

1. PlanningSpace does not return `Access-Control-Allow-Origin` for the Excel Agent Web App origin. This cannot be fixed by adding CORS headers in the Excel Agent ASP.NET app while the browser calls PlanningSpace directly.
2. `env.Tenant` can be `null`, and `psVersionSlice.ts` inserts it into the URL without validation.

Relevant code:

- `src/environment.ts`: tenant comes from query parameters/session storage.
- `src/taskpane/features/psVersionSlice.ts`: constructs `${PlanningSpaceBaseUrl}/${Tenant}/api/tenanthome/getversion`.
- `Manifests/manifestDev001.xml`: the fallback `DefaultSettings/SourceLocation` has no tenant/clientId query, while the VersionOverrides `Taskpane.Url` does.

The configured tenant `atlantis` currently returns an HTML `Tenant disabled` page from the dev cluster.

Possible code-side solution:

- add a same-origin ASP.NET proxy endpoint for the PlanningSpace version request;
- validate/escape the tenant server-side;
- make the UI call `${ExcelAgentApiUrl}/api/...` instead of calling PlanningSpace directly;
- do not send the request when tenant is absent;
- add tenant/clientId to the manifest fallback SourceLocation.

This CORS/proxy change has not been implemented or committed; it should be a separate behavioral change from the Docker update.

### Configuration model

- The standard pipeline (`814`) runs without `ASPNETCORE_ENVIRONMENT` and loads UAT1 from `appsettings.json`.
- Docker keeps `ASPNETCORE_ENVIRONMENT=DevCluster` for non-development middleware behavior, but deployment-specific URLs come from App Service settings generated by `ps-bicep`.
- The temporary `appsettings.DevCluster.json` URL overlay was removed; `appsettings.json` remains the UAT1/default artifact configuration.
- The temporary `env.devcluster.js` was removed. Deployed React configuration is generated by the ASP.NET `/env.js` endpoint from the same effective .NET configuration.
- Pipeline `814` no longer copies `env.dev.js` into `wwwroot`; this keeps React and .NET on the same effective configuration.
- Runtime `ExcelAgentApiUrl` is emitted as `window.location.origin`. This avoids an `http://` URL behind Azure App Service TLS termination and prevents mixed-content failures.
- Bicep supplies `PlanningSpace__BaseUrl` and `PlanningSpace__Identity__Authority`; these App Service environment variables are authoritative for container deployments and feed both .NET and runtime `/env.js`.
- Bicep supplies `Product: 'Planning Space'` in `standardTags`, satisfying the sandbox Azure Policy.
- `PlanningSpace:Identity:RefreshTokenBufferInMinutes` remains `5` in `appsettings.json`. It does not need a Bicep variable; the code also falls back to five minutes for missing/non-positive values.
